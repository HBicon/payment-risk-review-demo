# 收款风控人工审核原型

一套围绕订单 `TCB2026110949852` 的收款风控流程原型，包含移动端用户流程与独立的桌面审核台。页面之间通过浏览器 `localStorage` 共享审核状态，全部为前端交互演示，不依赖后端服务。

## 页面入口

- `index.html`：统一演示入口，集中进入用户支付、资料上传、等待结果与独立审核台。
- `payment.html`：支付页与整体风控弹窗。弹窗会在页面载入后自动展示，也可点击「去核验」再次打开。
- `upload.html`：本机图片、IMEI 图片重新上传页。支持选择、拖拽、预览、移除和格式校验。
- `waiting.html`：人工审核等待页，并承载审核通过、驳回终止、重新上传三种状态。
- `review.html`：独立审核台，包含待审队列、证据原图、自动初审结果、命中规则与审批操作。

## 演示路径

### 用户通过审核

1. 打开 `index.html`，点击「开始用户支付流程」，在风控弹窗点击「重新上传资料」。
2. 上传两张图片，勾选授权并提交。
3. 页面进入 `waiting.html` 等待态。
4. 打开 `review.html`，从待审核队列选择对应订单。
5. 点击「通过并付款」并确认。等待页会同步进入「审核通过，支付完成」。

### 用户被驳回

1. 在审核台选择驳回原因，点击「驳回并终止」。
2. 等待页显示审核未通过与原订单信息。
3. 点击「重新上传资料」会发起新的审核单，原审核单保持关闭状态。

### 跨浏览器会话演示

手机页与审核台若运行在两个隔离的浏览器配置中，存储不会共享。审核台右上角的「模拟新提交」按钮可在当前会话创建一条资料齐全的待审订单，便于单独演示审核台。

## 关键业务规则

- 风控触发：支付页展示整体风控提示，但不会直接执行付款。
- 资料重传：本机图片与 IMEI 图片均为必传项，同时需要用户确认授权。
- 人工审核：提交后进入待审核；审核台通过后立即将订单标记为已支付。
- 审核驳回：本次审核单关闭，支付流程终止；再次上传会创建新的审核记录。
- 审计留痕：审核员、审核时间、结论与备注写入审核单，并在详情页展示。

## 本地预览

```bash
cd outputs/payment-risk-review
python3 -m http.server 4173
```

然后访问 `http://127.0.0.1:4173/index.html`。

## 说明

- 示例图片位于 `assets/`，为 SVG 视觉样张，用于说明构图和信息要求。
- 二维码为视觉占位图形，不可用于真实支付。
- 数据保存在浏览器本地，清除站点存储后会恢复示例队列。
